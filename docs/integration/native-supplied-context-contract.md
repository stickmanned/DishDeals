# Native supplied-context v1 boundary

Pinned shared native-context v1 contract (Northstar integration decision): optional `nativeContext` object {version:1, textFragments:string[], registeredTypes:string[], receivedAt:number, truncated:boolean}. receivedAt Unix seconds (receipt clock ONLY, never publication time). At most8 distinct text fragments, each <=4096 UTF8bytes, combined <=12000 UTF8bytes;32 distinct registeredTypes, each <=200 UTF8bytes; finite nonnegative receipt clock. Full JSON <=24000 UTF8bytes. Retain original text including attributedContentText and supplied provider plain text, canonical link separate. Bounds/drop/load failure must set truncated=true rather than silently claiming full source. No model confidence/media-byte claims from types. Ingestion nativeContext is immutable first receipt: duplicate submission never overwrites existing context/manual caption. Context stays private, expires with owned item; never enters canonical public deal fields. Complete context accompanies user's actual recording into VLM prompt, separate from editable caption; evidence channel caption may quote either supplied text or manual caption via exact substring validation, not synthetic probability. Truncated source is visible and blocks automatic extraction until the user explicitly provides complete context or uses manual flow; never silently ignore loss.
Trusted native recovery bridge: web posts `{type:'requestShareContext',sourceUrl}` from configured HTTPS main frame. Native dispatches a CustomEvent `dishdeals:shareContext` whose detail is {sourceUrl,nativeContext}; serialize JSON safely, no interpolated source into executable JS/no context in route/query/log. Web accepts only exact current normalized sourceUrl and validates bounded shape. Existing recovery remains explicit user consent, not auto account submission. `received` receipt is only sent after genuine backend itemId and contains sourceUrl; context for that receipt is included in server submit atomically before native cleanup. Old context-less files/messages remain supported and cannot be misrepresented as complete context. Native direct authenticated submit sends nativeContext additively. No automatic containing-app opening, no Instagram resolver, no hidden/remote media. Source URL stays attribution.

Actual Instagram provider identifiers/representations remain pending a real iPhone sample. Registered identifiers mean offered types, not loaded bytes. Native and backend counterparts are separate bounded tickets, reviewed together. Harry implementation reused; this is integration hardening, not another extension.
