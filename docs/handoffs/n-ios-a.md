## 1. Source inventory (Harry branch, `83035c1..547a74d`, 87 files)

- **Framework: a native SwiftUI shell hosting the Next.js site in a `WKWebView`.** It is not React Native or Expo. The web app has to be served over HTTPS (`WEBSITE_URL`); the app loads `WEBSITE_URL + route` and refuses non-https.
- **Project definition:** `ios/project.yml` (XcodeGen), deployment target iOS 16.0, Swift 5. Generated `.xcodeproj`, `Info.plist` and entitlements are git-ignored, so the YAML is the only source contract.
- **Targets and bundle IDs:** app `Dinedeals` = `dev.dishdeals.app`; share extension `ReelShare` = `dev.dishdeals.app.ReelShare` (`com.apple.share-services`, `APPLICATION_EXTENSION_API_ONLY`). Prefix `dev.dishdeals` is a placeholder. `DEVELOPMENT_TEAM`, `WEBSITE_URL` and `BACKEND_URL` are placeholders; the README says the team must set them.
- **Capabilities declared in the YAML:** App Group `group.dev.dishdeals` and keychain group `$(AppIdentifierPrefix)dev.dishdeals.shared`, on both targets. URL scheme `dinedeals`. No push/APNs entitlement.
- **Extension activation rule:** web URL (max 1) or text. `ShareViewController` loads a URL or text attachment, normalizes it, and accepts only a direct `instagram.com` / `www.` / `m.` `https` link whose path is `/reel/`, `/reels/` or `/p/<code>`, rewriting to `https://www.instagram.com/reel/<code>/`. Profile and `/share/...` short links are rejected with an on-screen message. It does not read images or video.
- **Files:** `ios/App/DinedealsApp.swift` (shell, bridge, notifications, deep link), `ios/ShareExtension/ShareViewController.swift`, `ios/Shared/ShareStore.swift` (keychain, App Group inbox, normalize, submit).
- **Auth bridge:** the web page (`components/reels/ReelIntake.tsx`) posts `{type:"session", token}` to `webkit.messageHandlers.dishdeals` using `useAuthToken()`. Swift accepts it only from the main frame whose origin matches `WebsiteURL` (scheme, host, port; WebKit's port 0 for default https is handled), and stores the token in the shared keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, service `DinedealsReelSession`). Sign out posts `null`, which deletes it. The extension has no refresh token and does not refresh; an expired token yields `ShareFailure.signIn`.
- **Submit path:** extension `POST {BACKEND_URL}/api/mutation` with `Authorization: Bearer <token>` and body `{path:"reels:submit", args:{text, retentionDays:7}, format:"json"}`, host must end `.convex.cloud`. Checked against the official Convex HTTP API page (`POST <CONVEX_URL>/api/mutation`, `path` as `module:function`, `args`, `format:"json"`, `Authorization: Bearer`, `{status:"success", value}` / `{status:"error"}`): matches. Whether the token Convex Auth issues is accepted here is untested.
- **AppGroups lifecycle:** every share first writes an atomic, `completeFileProtectionUntilFirstUserAuthentication` JSON file `{kind:"link", value, savedAt}` into `<group container>/ReelInbox` ("recovery copy"), then submits. On success it writes a `{kind:"item", value:<itemId>}` pointer and deletes the link file. On any failure the link file stays for 24 hours. The app consumes the inbox on launch and on `scenePhase == .active` (`ShareStore.first()` returns one file, oldest name first; expired or malformed files are deleted): an `item` pointer routes to `/reels?item=<id>` and is deleted; a `link` routes to `/reels?shared=<url>`, and is deleted only when the page posts `{type:"received", sourceUrl}` after the server accepts it. A `result` message schedules a local notification; no remote push.
- **Payload contract (extension to backend):** `reels:submit({text: string, retentionDays?: 1|7|30}) -> {itemId, duplicate}`. Server `normalizeInstagramUrl` (`lib/reels/contract.ts`) re-validates (one `https` link, three Instagram hosts, no credentials or port, `reel|reels|p` shortcode path) and stores `reelItems.sourceUrl`. The Swift and TypeScript normalizers are two implementations that must stay identical; the recovery-copy match in the `received` handler compares their output by exact string.
- **Backend added (additive schema):** tables `reelItems` and `reelLimits`; `convex/reels.ts` (submit, get, list, retry, remove, setRetention, saveDraft, internal helpers), `reelActions.ts` (`"use node"`; ScrapeCreators retrieval and Gemini video extraction), `reelWorkflow.ts` (`@convex-dev/workflow` 0.4.8), `convex.config.ts` (declares optional env vars `REEL_PROVIDER_USAGE_AUTHORIZED`, `SCRAPECREATORS_API_KEY`, `GEMINI_API_KEY`, `GEMINI_REEL_MODEL`), `lib/reels/{contract,provider}.ts`, `components/reels/ReelIntake.tsx`, `app/reels/`.
- **Frontend (not native):** `components/frontend/*`, `lib/frontend/*`, fonts and images, a sign-in and profile UI, and `Discover`, `Post`, `DealDetails`, `JobPanel`. `app/layout.tsx` and `app/page.tsx` are replaced (home is now `Discover`; the T-03 test page and the T-03 `AuthControls` mount are gone).
- **Hosting prerequisites (from the YAML and Harry's README, not exercised):** a reachable HTTPS site for the web app (a Windows localhost URL will not work on the phone), a Convex cloud deployment URL used for both the web app and `BACKEND_URL`, a development team that can provision the two capabilities, unique bundle IDs, XcodeGen to generate the project, and a physical device (no push, so the extension cannot be proven in a simulator end to end).

## 4. Reel draft versus the canonical form adapter

`lib/reels/contract.ts` `reelDraft` (strict): `restaurant|null`, `address|null`, `dealText|null`, `price|null`, `currency|null` (ISO code, any currency), `validDays|null` (null means unknown, `[]` means confirmed every day), `validStart|null`, `validEnd|null`, `expiresOn|null`, `conditions|null` (null unknown, `[]` confirmed none). `reelExtraction` adds `isDeal`, per-field `evidence[]` (caption / audio / visual, quote, timestamp), `transcript`, `warnings`. Confidence is not requested.

Mismatches with canonical `DealOffer` / `DealResult`:
1. **`toCanonical` fabricates `confidence: {restaurant:0, priceCad:0, hours:0, expiresOn:0}`** (`lib/reels/contract.ts`, last function). Zero is not "unknown": it asserts the model is certain the field is wrong, and a UI that highlights scores under 0.6 would treat every reel field as low confidence for the wrong reason. This is the semantic mismatch the packet asked about. It is not called anywhere in the inspected UI or backend, so the damage is latent. No guessed scores are proposed here: `DealOffer.confidence` is optional and the adapter should omit it. `DealResult` itself requires all four numbers, so a true `DealResult` cannot be built from reel data without a contract revision.
2. `price` and `currency` split versus `priceCad`. `toCanonical` sets `priceCad` to `price` only if `currency === "CAD"`. For any other currency the amount is dropped silently. The canonical adapter should instead emit `priceCad: null` plus a non-blocking `CURRENCY_UNVERIFIED` note with `originalAmount`.
3. `validDays: null` and `conditions: null` (unknown) have no counterpart in `DealOffer` (`Weekday[]`, `string[]` only). Passing `[]` would silently mean every day or no conditions, the exact thing Harry's own comments forbid. Whether the canonical reducer's `isReviewed` flags make `[]` safe was not tested here. This needs a test, not an assumption.
4. `restaurant: null` maps to `""` (canonical: unknown restaurant is blank, not a rejection).
5. No `startDate` and no unsupported-constraint field in `reelExtraction`; canonical `ManualReviewNote` carries `FUTURE_START` and `UNSUPPORTED_CONSTRAINT`. Reel extraction cannot currently report either.
6. Evidence model is richer than canonical (per-field quote and timestamp). It has no canonical home, so keep it as a sidecar on the draft, never in `DealResult`.
7. Currency evidence: Harry requires evidence for a non-null `currency`, but it is the model's quoted text, validated against the caption or its own transcript. Canonical `extractCore` verifies CAD quotes against caller-supplied text only. For video audio and visual quotes nothing independent verifies the quote, as Harry's README already says.
8. Two extraction stacks now exist: canonical `lib/extractCore.ts` (image/text, REST, strict, `DealResult` sidecar) versus Harry's `reelActions.ts` (video, `@google/genai` SDK, `z.toJSONSchema`, own retry/timeout). Different model env (`GEMINI_REEL_MODEL` versus the T-05A models), different failure taxonomy.

## 5. Ranked policy and risk findings

1. **Provider/policy conflict.** The canonical plan forbids server-side Instagram scraping and T-05A rejects URL-only input as unsupported. Harry's backend retrieves the video through ScrapeCreators (a third-party scraper API) and sends it to Gemini. It is off unless `REEL_PROVIDER_USAGE_AUTHORIZED=true` and both keys are set. This packet does not authorize the resolver; it needs an explicit decision by William and Northstar, plus a billing and privacy decision. A URL receipt is not video understanding.
2. **Free-account capability blocker (see section 1).** The design depends on App Groups and Keychain Sharing; if Apple's table is as fetched, a free Personal Team cannot build the extension flow.
3. **Two Convex deployments and three clients** (section 2). Reels (canonical deployment) and the feed/post/detail UI (teammate deployment) do not share data, auth session or user IDs.
4. **Account binding of queued links.** A recovery link is stored with no account identity. If user A shares offline, and user B is signed in when the app next opens, the page auto-submits A's link under B (`ReelIntake` effect on `shared`). The owner contracts say pending drafts must not be silently assigned across accounts. Server ownership itself is sound: `owned()` checks `ownerId`, `expiresAt`, `getAuthUserId`.
5. **Lost edits.** `reels.saveDraft` is last-write-wins on `draftJson` with no revision or generation check, so two tabs or devices overwrite each other silently. The editor key is `itemId-generation`, so a retry resets the editor, but a stale save is only blocked by `status !== "ready"`. A real guard needs an extra stored field, which means an owner-agreed schema change.
6. **Retries and receipts.** Server dedupe (`by_owner_url` `.unique()` inside one mutation) and the 10-per-hour limit look sound; retry cap is 5; stale `generation` guards protect late workflow steps. Remaining client risks: the extension cannot refresh its token, only one inbox file is consumed per activation, and the identical-route guard in `WebShell.updateUIView` ignores a repeated identical route.
7. **Extension scope.** It handles URL or text only, with a strict Instagram host/path allowlist. Instagram might share something else (an image, a video file, or a short `/share/` link); that is the pending device capture. A rejected payload shows a message and saves nothing.
