## Behavior and chosen limits
- Request: one user turn = labeled JSON context text, then every supplied image in order. Caption, text and supplied `publishedAt` are all included. `provenanceUrl` is accepted only to detect URL-only input; it is never fetched and never sent to the model. Today's date is never sent, so it cannot stand in for a publication date.
- URL-only -> `UNSUPPORTED_SOURCE`. Nothing supplied -> `EMPTY_SOURCE`.
- Limits: 8 images, 5MB per image, 18MB total request estimate (base64 images + text; under the 20MB cap), caption 10,000 chars, text 20,000 chars, 10 deals, 45s timeout. MIME allowlist PNG/JPEG/WEBP/HEIC/HEIF plus a magic-byte check. Native resize/HEIC/video preparation is separate and pending the runtime decision.
- Attempts: primary, primary once more, then `gemini-3.5-flash-lite`. Timeouts, network errors, 429/5xx, unfinished/malformed/invalid output are retried. 400 skips to the fallback. Auth (401/403), safety blocks and local input errors stop at once. Errors are fixed safe strings; provider bodies, URLs and the key never appear in them.
- Validation: strict Zod plus finite 0..1 scores (all four required), finite nonnegative price, real ISO dates, `HH:MM` 00..23, weekday enum with no duplicates, non-blank `dealText`, `isDeal` consistent with `deals`. Unknown restaurant is `""`, not a rejection. No 0.5 default, no global score, no threshold rejection; scores are the model's self-assessment, not probabilities. Everything returned is a suggestion for explicit user acceptance.
- Manual-review notes (returned in `manualReview`, never folded into `conditions`): `FUTURE_START` (start date after today in America/Vancouver), `UNSUPPORTED_CONSTRAINT`, `CURRENCY_UNVERIFIED` (price without model-quoted CAD evidence). A caller must not treat a deal with notes as currently valid.

## Integration blocker to record (no schema change made)
The canonical `Deal`/`DealResult` has no `startDate`, no unsupported-constraint field and no currency evidence. The core returns these beside the canonical result in `manualReview`. A future `extractDeal` that returns a bare `DealResult` would lose them, so the owners need an agreed contract (a sibling field or a draft adapter) before that action is written.

## Review corrections (second commit)
1. **Deadline now covers the body.** One timer spans connect, headers and `response.json()` (raced against an abort); a stalled body yields a sanitized `PROVIDER_TIMEOUT` and is retried/falls back like any timeout. A body read that errors yields a sanitized `INVALID_MODEL_OUTPUT`. `timeoutMs` must be finite, > 0 and <= `LIMITS.maxTimeoutMs` (120,000); otherwise `CONFIGURATION` before any call. Default 45,000. Tests use a ReadableStream whose headers arrive but whose body never closes.
2. **Strict model schema.** `ModelResult`, `ModelDeal` and `confidence` are strict objects; the only sidecar fields are `statedPrice`, `cadEvidence`, `startDate`, `unsupportedConstraints`. An unknown key (for example an unmodelled start constraint, `warnings`, a scalar `confidence`) is `INVALID_MODEL_OUTPUT`, never stripped.
3. **Image signatures.** PNG needs the full 8-byte signature. HEIC/HEIF needs a valid `ftyp` box (size >= 16 and within the file) whose major brand is an HEVC-image brand, or a generic `mif1`/`msf1` major with an HEVC-image compatible brand. MP4, AVIF and truncated boxes are rejected. This is signature validation only, not proof the file decodes or that the provider accepts it; that needs a live call.
4. **CAD.** The model now reports `statedPrice` (amount as shown) and `cadEvidence` (exact text). Canonical `priceCad` is set only when the quote appears in the caller-supplied caption/text (whitespace/case-insensitive) AND itself names CAD. Otherwise (no quote, quote lacks CAD, quote not in supplied text, or an image-only claim) canonical `priceCad` is `null` and the amount survives only as `originalAmount` on a non-blocking `CURRENCY_UNVERIFIED` note for a manual CAD choice. Image quotes are never treated as verified ground truth. All fields remain suggestions; scores remain self-assessments.
5. **Internal envelope contract.** `ExtractOutcome = {result, manualReview, requiresBlockingReview, model}`. Notes carry `dealIndex` (index into `result.deals`) and `blocking`. FUTURE_START and UNSUPPORTED_CONSTRAINT are blocking; CURRENCY_UNVERIFIED is not. A caller must carry blocking notes by deal index to the form and must never return or store `result` alone. The public `extract.extractDeal` remains unimplemented until an owner-agreed envelope and the upload ownership contract exist; no schema or API revision is implied.
