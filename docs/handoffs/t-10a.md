## Contract for Harry (API owner: Northstar)
`api.deals.get({ dealId: Id<"deals"> })` (optional auth) returns `null` when the deal is missing/deleted, otherwise the canonical `deals` document (all stored fields, `_id`, `_creationTime`, counts, `imageId`, `lat`/`lng` unchanged) plus:
- `authorName?: string`: author's `profiles.displayName` (by `by_user`); omitted when the author has no profile (never invented).
- `authorWallet?: string`: profile `walletAddress`; omitted when absent.
- `imageUrl: string | null`: `ctx.storage.getUrl(imageId)`; `null` with no image or a missing file. No bytes are fetched.
- `viewerVote: "still_on" | "expired" | null`: the caller's own vote via the server-derived `getAuthUserId` and `votes.by_deal_user`; `null` when signed out or not voted. This fills the plan's unnamed "viewer's vote"; canonical tables are unchanged.
- No `distanceKm` (no viewer location argument exists; nothing is inferred as 0), no validity/status fields, no email, phone, name, session or other auth-private user data.

`returns` is `v.union(schema.doc("deals").extend({...}), v.null())` (`schema.doc` and `.extend` verified in installed Convex 1.46 types and generated guidelines). The validator is enforced: adding a stray `email` key to the return fails the tests.

Corruption path (review fix): the author profile (`profiles.by_user`) and the viewer's vote (`votes.by_deal_user`) are read with `.unique()`, matching auth/votes. Duplicate rows violate the one-owner invariant, so the read throws instead of picking an arbitrary payment wallet, display name or vote fact. The thrown Convex error carries no wallet, name or email text (asserted). Duplicate author profiles fail the read for every caller of that deal; duplicate votes by one viewer fail only that viewer's read (other viewers and signed-out reads are unaffected). Reads write nothing in either case. Normal reads are unchanged. This is deliberately not tolerant first-row selection.
