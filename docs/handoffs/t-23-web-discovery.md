# T-23: Search outside the community catalog

Explicit user assignment: automatically look online when a restaurant query (for example, Haidilao) has no stored data. Branch `t-23-web-discovery` depends on `t-22-smart-sharing` at `0a73f3e` and uses the existing isolated frontend checkout. The dependency includes waiting for Convex to confirm guest authentication before protected requests; token generation alone is insufficient.

Discover accepts restaurant names or dining questions, supports Search and Enter, and transparently checks published offers first. Empty results invoke server-side Gemini Google Search grounding. Web findings remain an ephemeral response, displayed separately with cited public sources, query time and sanitized provider search suggestions. They are never imported into the offer database or a search index. The same findings panel is available in `/tools/`. Detail pitches never search unrelated websites; missing required budget currency or location still asks for clarification. Authentication, owner isolation and the existing 60/hour search quota remain in place. Keys stay in Convex. `GEMINI_WEB_SEARCH_MODEL` can optionally select a separately supported grounding model.

Validation: typecheck and lint passed; 198 app/backend tests and 23 repository workflow tests passed; GitHub Pages export built; production dependency audit found zero vulnerabilities. Backend tests confirm actual grounding is required, unsafe or uncited sources are excluded, memory-only answers are rejected, non-empty/detail queries do not call web search, failed providers do not expose their bodies/keys, and online findings create no jobs or offers.

Browser QA at 1280px and 390px verified the source form, Search/Enter controls and a real published Cactus Club result. A guest authentication timing failure found during final QA was fixed by waiting for backend-confirmed authentication; the search was repeated successfully with no new warning/error logs. Provider suggestions use sanitized HTML in a shadow root so branding styles cannot change the app's filter controls. Live grounded-findings rendering remains pending the quota setup below.

Live sharing acceptance: the unified form submitted only `https://www.cactusclubcafe.com/locations/broadway-ash/`, with no image or caption. Convex job `kh7dy8gsrpex4zqpbt6xpks73x8fmmbj` completed with two real source-backed offers, both held for manual review, including unknown-currency/date warnings and map package 0.2 branch candidates. No test offer was approved or published.

Live blocker: the deployed `gemini-3.5-flash-lite` handles extraction/intent but Google Search calls return HTTP 429 `RESOURCE_EXHAUSTED`. Google's current pricing marks Search grounding unavailable in its free API tier. A focused check of the listed legacy `gemini-2.5-flash-lite` returned HTTP 404: unavailable to new users. No billing, paid account or unsupported bypass was enabled. The key's project owner must configure appropriate grounding quota/billing, then a live empty-catalog query must be repeated. Until then, the app shows a clear online-search failure and provides a user-operated external search link. Grounded-result browser acceptance is pending; mocked tests are not evidence of live search success.
