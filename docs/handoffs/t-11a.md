## Behavior
- Signed-in check via `getAuthUserId`; the user id is never an argument (extra `userId`/count args are rejected by validators). No profile required (the plan's auth contract has none for voting). The deal author may vote.
- Missing deal throws "Deal not found". The `by_deal_user` index plus `.unique()` finds the caller's vote (a duplicate-row corruption throws).
- First vote inserts a row and increments the selected counter. The same vote again is a no-op. A switch patches the same row, decrements the old counter and increments the new one once. Counters and row change in one mutation transaction, with all validation before the first write.
- Both counters must be safe integers >= 0 or the call fails ("Deal vote counts are corrupt"). A switch whose old counter is 0 fails ("inconsistent"). Nothing is repaired or fabricated. The core does not compare counters to vote-row totals, so seeded demo deals with counts but no vote rows still work.
- No vote removal API; no schema or name changes.
