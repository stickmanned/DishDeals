## Evidence and findings

1. **Image selection is local preparation, not a storage upload.** `Post.choose` compresses the file to a JPEG data URI. Submission passes base64 through `workflow/jobs:submit`; `workflowJobs.inputJson` holds the validated source and a scheduled action calls Gemini. There is no storage-upload call in this path. Selection alone does not run extraction. Preview mode bypasses submission/extraction and requires manually filling a draft.
2. **Live feed images are missing by construction.** `workflow/ai:finish` stores extracted outcomes without source media, `workflow/deals:listForMap` returns no image URL, and `parseWorkflowDeals` never sets `imageUrl`. The existing frontend integration test explicitly expects it to be absent. This explains a missing published-feed photo even after successful processing. Durable source-image storage/feed display is a separate implementation task; it was not introduced during this investigation.
3. **Browser decoding had one fragile path.** It called `createImageBitmap` without checking availability/falling back, rejected HEIC and absent MIME metadata before decode, and did not validate JPEG canvas output. These are plausible iPhone preparation failures, not a proven explanation of the teammate's specific test.
4. **Native sharing uses a different pipeline.** Instagram → `ShareViewController` → URL normalization → App Group recovery file → shared Keychain session → `reels:submit` → private Reel processing. The app later opens `/reels`, not the community `/post` form. Private Reel drafts do not publish to the feed. Previously the extension selected URL OR text, swallowed loading errors and discarded unsupported inputs; shortened `/share/...` links remain unsupported. No automatic resolution/scraping was added.
5. **Read-only live readiness check:** the repo-documented `proper-marmot-82.ca-central-1.convex.cloud` deployment returned `status: success`, `geminiConfigured: true`, `geoapifyConfigured: true`, **`reelsConfigured: false`** from `trial:status`. This checks environment-presence flags, not valid credentials/quota/provider performance. If the teammate's Xcode build points to this deployment, Reel processing is blocked by setup. The actual iPhone's build/URLs remain unconfirmed.
6. `ios/project.yml` still has placeholder website/backend defaults and no signing team. The built app and extension must share the real App Group and Keychain entitlements and point to matching frontend/backend deployments. Pulling source does not update the hosted website or rebuild an installed app; the existing Pages build is a separate publication step.

## Changes

- Image preparation falls back to the regular browser image loader, releases bitmap/object URL resources, handles empty MIME metadata and attempts browser-supported HEIC/HEIF decoding before JPEG conversion. Unsupported HEIC still returns a visible instruction to use JPG. Input size, JPEG signature and compressed payload limits remain enforced.
- Source intake diagnostics report picker metadata, preparation stage, preview load/error, runtime mode, authentication/connection, backend configuration flags and backend job receipt. Job diagnostics show ID, status, Vancouver update time, failure code and offer publication/review counts. No base64 image or credential is logged.
- The extension displays selectable bounded received text, registered attachment types, loaded value type and provider loading error codes. It tries URL, plain text and text representations, including UTF-8 Data. It distinguishes local saving, session absence, backend configuration/HTTP failure and accepted server receipt.
- Unsupported textual shares can be inspected after reopening the app; they stay local and never submit automatically. Raw text is capped at 4096 characters and the receipt at 12000. Newer inbox records take precedence over old unsupported input. Expired records are cleared during inbox inspection. App Group misconfiguration returns a visible save error rather than force-unwrapping its container.
- Incoming web shares are visible before sign-in. A frontend built without `NEXT_PUBLIC_CONVEX_URL` now shows the receipt and an explicit unconfigured message, instead of calling hooks with no Convex provider. Website base paths tolerate a trailing slash.
